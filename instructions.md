# XMALab Local Integration Instructions
These notes describe how this repository participates in the local 3-repo workflow together with `../XROMM_DLCTools` and `../DeepLabCut`.
## 1) Expected local layout
Recommended sibling checkout layout:
- `XROMM_DLCTools/`
- `DeepLabCut/`
- `xmalab/`
`XROMM_DLCTools/scripts/baseline_harness.py` uses `../xmalab` by default when validating cross-repo integration.
## 2) XMALab’s role in the workflow
Within the integrated workflow, XMALab provides:
- the canonical 2D point CSV import/export contract
- the review / correction environment for predicted points
- the downstream consumer of `*-Predicted2DPoints.csv` / `.h5` artifacts generated by `XROMM_DLCTools`
The baseline harness validates the CSV contract against `src/core/Trial.cpp`.
## 3) Local build notes
Configure and build normally with CMake:
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```
Run the app from:
```bash
build/bin/XMALab
```
On macOS bundle builds:
```bash
build/bin/XMALab.app/Contents/MacOS/XMALab
```
## 4) Integration validation from XROMM_DLCTools
Run these commands from `../XROMM_DLCTools`:
```bash
uv run python scripts/baseline_harness.py --scenario xmalab_csv_contract --output-dir baseline_artifacts/xmalab_csv_contract --xmalab-repo ../xmalab
```
Full multi-repo suite:
```bash
uv run python scripts/baseline_harness.py --scenario all --output-dir baseline_artifacts/integration_all --deeplabcut-repo ../DeepLabCut --xmalab-repo ../xmalab
```
True end-to-end local workflow scenario:
```bash
uv run python scripts/baseline_harness.py --scenario phase3_local_workflow_e2e --output-dir baseline_artifacts/e2e_local_workflow --deeplabcut-repo ../DeepLabCut --xmalab-repo ../xmalab
```
## 5) Contract details that matter
The integration checks assume XMALab continues to accept/export marker columns in the established `marker##_cam#_{X,Y}` layout and preserves `NaN` handling used by the current `XROMM_DLCTools` export path.
